# v0.23（双端补齐）

> **状态**：2026-09-28 用户授权「按照你说的来改，然后把剩余规划都给做了」后发布。
> 出口条件中的语音/权限**真机矩阵（T3.1/T3.2）与升级闭环（H8）仍未在实物设备上跑**
> （无设备通路），作为已声明的残余风险记录在文末，不假装做过。

## 加了什么

- **日程（网页 + 安卓，同一套界面）**：设置里多一个「日程」，一天一份清单。
  日期选择是一整张**月历**：年和月都能翻（往前最多翻到今天所在的这个月），
  今天以前的日子灰着点不动；有安排的日子描一圈、底下打一个小圆点。
  点某天看那天的安排；添加、改文字、
  选时间（点开就选，不用手输：手机弹滚轮/表盘，桌面弹原生面板；24 小时 `HH:MM`，可留空）、
  勾选完成、删除都在原地做，**改动要点「保存」
  才写回服务器**——保存是整天替换，同一份内容存两次结果一样，重放不会出错。
  有没保存的修改时换日子，会先问一句，不会闷声盖掉你写的。
  「今天」以服务器日期为准：设备把系统时间改了，问出来的也不是别人的一天。
- **安卓原生：编辑消息并重新生成**：长按自己的消息可改可重发，改完从那条之后重新生成，
  与网页版同一套行为。
- **安卓原生：导出本次对话**：一键导出，文件直接落到系统「下载」目录并给一条已下载通知
  （本版不做分享面板）。链接过期会自动重签一次再试。
- **应用内一键更新**：关于页能查新版、下载、校验、拉起安装；下载与校验只走自建服务端
  这一个入口。

## 优化了什么

- 日程的日期选择从"横着八个格子"升级为整张**月历**：翻年翻月、今天以前点不动、
  有安排的日子描圈打点（2026-09-27 评审第 1 条）。
- 时间不用手输：点开就是选择器，手机弹滚轮/表盘，桌面弹原生面板，可清除留空
  （2026-09-28 评审第 3 条）。
- 换天不再闪一帧空面板：取数期间旧清单置灰留着，新数据回来整体替换
  （2026-09-28 评审第 2 条）。

## 修了什么

- 更新链路的地基问题：此前客户端直连 GitHub 取发布信息，GitHub 一侧漂了就表现为
  「检查更新失败」而自家服务端其实好着。现在这条直连被封死，改走自建服务端。
- 日程与导出的错误提示不再由客户端自己造句：服务端怎么说，界面就怎么显示
  （例如日期写错时提示「日期要写成 YYYY-MM-DD」），也不会把一句问错了的话
  渲染成「这天还没有安排」。
- 日程（2026-09-28 真机反馈三条，双端同修）：
  ① 编辑行开着直接按保存，刚写的字不再被「事项不能是空的」顶掉——编辑内容实时
  进草稿，保存前空行自动滤掉；② 换天取数时旧清单置灰留着，不再闪一帧空面板；
  ③ 月历上点 28 号要按两下的问题已修（渲染改成"内容真变了才重建"）。

## 注意（这一跳请手动装一次）

- **v0.22 → v0.23 需要手动安装一次**：应用内更新是从 0.23 开始才有的能力，
  手上还是 0.22 的设备这一次仍要下载 APK 自己装。装上之后，
  **0.23 → 0.24 那一跳起才是在 App 里点一下就完成**。
- 网页版随服务端部署即生效，没有独立发布动作。
- 日程数据存在服务端，换设备、换浏览器登录同一账号看到的是同一份。
