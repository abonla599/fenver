# v0.39.1 更新说明

<!-- scope: server-only -->

本版只换服务端，**没有新的安卓包**：安卓 `versionName` 仍是 0.36.4，检查更新按现有清单报最新可安装版本。线上此前跑的是 v0.38.4（官网整轮改版），而 v0.39.0 那一版从未上线，所以这一版把它那一整批连同本轮的出站与启动环境修复一起带上线——下面按用户看得见的变化重述，不必回头翻 v0.39.0。v0.38.4 说明里留着"应用内文案不在本版"的那批提示语，这一版随服务端到了网页端。网页版 App 打开 `/app` 就是「模型驾驶舱」；同一批改动在原生 App 里的那一份这一版不发，等下一版随安装包一起走。

## 新增了什么

- **上下文环**：输入区那枚模型芯片左边多了一圈环，画的是这一轮上下文在当前模型预算里的位置。有上一轮服务端回传的真实用量时按它校准，校准比值有上下界，一次异常回账拉不飞读数；第一轮还收不到时读数是客户端自己估的，账本里明说这一格是估的、首轮回账后自动校准。
- **上下文账本**：点环翻开一面账本——当前模型、已用与预算各是多少，用量拆成角色设定 / 历史 / 本次输入 / 其余几段（其余那截是系统提示与检索注入，客户端不假装认识服务端注入了什么），下面就是预算滑杆和两颗按钮。
- **「轻量整理」只切这一轮发什么，不动你存着什么**：按当前预算从最近一条往回收，说清收回几条、腾出多少；点「恢复完整发送」这一轮就整段发。历史原文是用户资产，这一格从不删它。
- **上下文预算按模型各存一份**：滑杆拖出来的数记在"这个账号 + 这条模型"上，换模型跟着换，互不串。存着的预算越过被调低的新上限时，卡上会说一句夹成了多少、多出来的那部分不会带上，不静默改。
- **接力队列**：正在回答时又发的消息先进一条队列，上一条正常结束后自动接力发出。队列上写着待发条数，有「暂停 / 继续」和「清空」，每一条还有一颗「立即插话」。队列只在内存里、每个标签页一份，不进本地存储，换身份即清空。
- **自动接力只在几个条件都成立时才走**：上一条正常结束、还在同一个会话、还是同一个人、页面在前台。缺任何一个就把那条放回队首并暂停，等人点「继续」——看不见的页面上不替你花钱发下一轮。
- **「立即插话」**：当前这一轮一终止就优先发这一条。切了会话或换了身份就不发，条目放回它原来那个会话的队列并暂停；带图片而当前模型读不了图的插话同样不发，并把原因说出来。
- **模型菜单变成两栏**：左边是可用模型清单，右边是这条模型的卡——本会话预算、模型上限、思考能力、设为这条、管理此模型，底下那颗「模型管理」是能力编辑区的总开关。桌面鼠标悬停只换右栏内容，手机没有悬停，改成点一行展开。
- **终帧回传本轮 token 数**：流式跑到结束、以及中途被停止的那一帧，都带上本轮的用量；环与账本的读数靠它校准。
- **模型卡上写清这条归谁改**：共享条目的上游和账本是全站共用的，能力与上限只有管理员改得动；普通用户在卡上看得到结论，改不了别人那条。

## 管理端

- **管理员的高危写操作会先确认一次身份**：新增、编辑、删除模型服务，设为默认，两条试连（已存的那条和表单里还没保存的那条），保存或删除搜索 key，以及记忆面那一项写操作；管理端那一片路径下的写操作同样要这张票（增删用户、停用与启用、重置口令、轮换 token、写配置都在这一片里）。凭据新鲜度不够时服务端先回一句要求二次验证，页面弹出口令框，填对之后刚才那一步自己接着做完。验过的这一次由服务端记在当前进程的内存里，浏览器只留一枚跟着它走的凭据；隔一会儿就要重新验，服务端重启之后这一格跟着作废。想建一个真实的 admin 账号，走 `tools/create_admin_account.py` 那条停服期的离线路径。
- **这道确认看的不再只是地址前缀**：模型服务、搜索 key、记忆衰减这几条管理员专属的写口挂在别的路径下，只靠一条前缀下一次新增路由就会再漏一次；现在这几条口挂的是同一张票。口令连着填错太多次会被暂时挡下，这笔账记两本：一本按"这个账号加这台来源"，另一本只按账号、跨所有来源合起来数——换着来源轮流试口令的人撞的是后一本。第一本按来源分格，同一来源上的别的管理员不互相挡；第二本的上限比第一本松，撑它的是第一本已经把来源分开了、而且这一步成功换票也不清账。这个"松"在取不到账号身份的退路那一格上确实更宽，这是有意接受的取舍，不是笔误。两本都只占二次验证自己那一格，登录与注册那几笔账各记各的。

## 优化了什么

- **模型上限与思考能力挪出连接表单**：新增或编辑模型服务的那个表单不再有「上下文上限」那一格——上限是模型的本事，不是连接配置，改到模型卡里配。点预置模板时会说一句：这份初始上限只随这一次新建发出去，之后归模型卡改。
- **「设置」页那行「上下文长度」退场**：滑杆住在账本和模型卡里，两处读同一份按模型存的预算，设置页不再留第三份真相。
- **环、账本、整理、实发用同一个模型口径**：这几处原先各读各的当前模型，分叉过一次；现在都从同一处取，显示降了实发才真的降。清单为空时环归零并如实说"暂无从算起"，不把上一轮的旧填充留着装作还在。
- **界面说的话与请求体一致**：思考那一格只在服务端说这条记录已核实、且这台设备上的开关开着时，才许说"按默认档发"；其余情况老实讲这一轮不发这一格，并给出不发的原因。填得超过服务端上限时，卡上先把那句拒绝原样说出来，界面不替你悄悄砍掉多出来的几档。这条记录当前的清单里找不到你存过的那一档时，界面回到默认档并把"为什么自己变了"说一次，换身份后这句一次性的话跟着清掉。
- **思考那一格今天什么都不会发出去**：服务端那份生产登记表里目前只有「不发思考参数」这一条，配方要真调用核实过、且核实结论绑在这条记录的地址与模型上，才登记得进去。所以这一版之后出网请求里不会出现思考档位那一格；卡上说的是"这条记录未核实"，不是"这个模型不会思考"——这两件事分得开。
- **每一道回落都不硬发档位**：这一格没发成有几道各自的原因——记录还没被核实到、存的档位序号超出它此刻的清单、配方拒收当前这份组合。几道都收在同一处：这一轮不发档位那一格，请求体里不会出现它，也不会因为它把一次正常调用演成失败。能给出去的字段只到这条模型服务的标识、状态、序号和一句固定文案——档位原文、配方名、地址与任何凭据都不在里面。这几行只走调试级输出，而本服务没有配置日志级别、默认级别不收调试级，默认启动下看不见，真要靠它排障得手动把级别调到 debug。
- **官网「谁能看到我的数据？」那条说得更准了**：反馈是例外——你提交的正文、连同随反馈附上的截图，管理员处理反馈时读得到；其余的都按账号分开存，会话、记忆、附件别的注册用户碰不到。

## 修复了什么

- **创建模型服务不再认客户端自带的标识**：从前"新建"时带上一个已存在的 id 走的是覆盖那一条的路——覆盖共享那条，全站的上游与密钥会换成发起者填的；覆盖别人名下的私有那条，主人之后的每次聊天都在花别人的钱、走别人的模型。现在自带非空标识一律当场拒回；带了但只是空白（空串、空格、制表）就地归零，由服务端生成新标识。
- **网页版的搜索不再把第三方密钥存在浏览器里**：设置页「搜索」那一格改成把查询交给本站转发，密钥只在服务端取用，返回只有结果和一句原因，界面上也不再出现源站地址。探测页 `probe.html` 仍留着手动的浏览器直连，那一格是给人排障用的，密钥只活在这一页的内存与请求头里。
- **老版本留在本机的明文凭据，清理范围扩到搜索密钥一族**：网页版一直在页面加载时扫一遍本地存储、删掉旧版本留下的明文设备密钥；这一版把搜索源那一族的明文密钥并进了同一份名单、同一个函数、同一次扫描，不另起第二处清理。隐私模式或存储被禁用时这一步安静跳过。
- **浏览器对外连接的白名单收窄到只剩本站**：全站页面原先还列着两条第三方搜索域（博查与 Tavily）的地址，而网页早就改走本站转发——多列一条就是多开一条浏览器能往外发的路，这一版把这两条摘掉了。探测页那一档一个字没动，它必须直连供应商才探得到东西。
- **出站请求不再读会话里的代理环境变量**：四处生产出网客户端（取安装包、云端嵌入、搜索源转发、网页搜索）此前会在**构造客户端的那一刻**就解析 `HTTP_PROXY / HTTPS_PROXY / ALL_PROXY / NO_PROXY`，一枚带方括号的 `NO_PROXY`（例如里面写着 `[::1]`）会让这一步当场抛错，而各处的降级分支把它吞成静默故障——记忆悄悄退回伪嵌入、取包失败、搜索回空。这一版这四处一律不读环境代理，并补了一把按构造点现扫的名册锁与一枚毒环境行为反例：反例先证明这枚毒真能让裸客户端抛错，再证明生产构造路径不受影响。
- **拉起后端之前先清会话代理变量**：看门狗、换包脚本、开机自启脚本在启动后端子进程之前，先删掉当前会话那四枚变量，并打印 `PROXY-ENV-SCRUBBED names=…`（只印变量名、不印值；一枚都没命中也印 `names=none`，日志能证明这步跑过）。手动换包配方与回滚指引也补了同一步。上一格是子进程侧的防线，这一格挡的是父会话里的毒随环境继承传下去；没有留旁路开关。
- **换包脚本的删除动作收成正向白名单**：代理清理这一步用的是删除命令，契约锁改成只认"删环境变量"这一种形状，删除命令的六个本机别名一律禁，并与本机实测的别名集合双向对账——防的是有人把这一步写成顺手删掉回滚目录。这一格不改运行行为，只让写歪的脚本在测试里当场红。
- **根级账本文件补一道兜底（内部加固）**：思考参数核实探针的 stdout 摘要里带现役密钥的 sha256 前 12 位指纹（不是密钥本身），它用的账本文件名形如 `call-ledger-*.jsonl`。探针自己已经拒收落在仓库里的账本路径，这一版再给仓库根的同名文件补一条忽略规则，并补一把真会红的哨兵锁与一条反向用例，兜住手工拷贝、摘要重定向、旧版探针这类绕过探针自身判据的落法。规则只锚仓库根，子目录里的同名文件不受它管。

## 边界与残余

- **没有新 APK**：不涉及 `android-native/**`、安装包签名、`versionName` 与更新通道；`/site/version.json` 保持原样（仍指向 0.36.4）。驾驶舱在原生 App 里的那一份、以及靠更新清单里那枚签名字段真验"清单没被改"，都要等下一版随安装包一起走；当前手机上的包看不懂那枚字段，会照旧忽略它。
- **自托管更新清单开始带一枚签名字段**：服务端已经把这一格放进清单并对形状把关，本版不让手机上的包多任何功能。
- **出站代理这一格还有两处已知缺口，如实记着**：取安装包那条路上另有一处走 `urllib` 的出站不在本次名册射程内——方括号毒不让它构造崩，但环境代理仍能改道（另登 #297）；另有一把旧锁只判「每处 `OpenAI(...)` 的实参文本里有没有出现 `http_client` 这个词」，注释或字符串里出现同名词也算数，因此可能假绿（另登 #296）；真正核对证书校验与主机名比对的是另一枚锁，不在此列。这两处本版都没兑现，不写成"已修"。
- **启动脚本的清环境只罩后端拉起**：隧道（cloudflared）那一支不在本次射程；块注释续行仍是文本锁自报的盲区。
