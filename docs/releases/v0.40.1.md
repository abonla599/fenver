# v0.40.1 更新说明

<!-- scope: server-only -->

本版只换服务端，**没有新的安卓包**：安卓 `versionName` 仍是 0.36.9，检查更新按现有清单报最新可安装版本。这一版收掉的是交接文档里那批质量债与安全欠账里**不依赖设备验证、边界清楚**的那些；十一项「结构性工程」只啃下两项（发版闸门缺的那一格、二次验证跨来源锁人），其余多数要动并发状态机或得真机验证，不在本版射程内——那句「逐项啃完」本来写在这里，是假的，已改掉。

## 安全

- **二次验证成功后清本人的失败预算**：两道限流闸都在验口令**之前**判，于是别人从任意来源把 ② 号那格（按账号计、30 次/10 分钟、跨来源）打满之后，**这位管理员本人在自己机器上拿着正确口令也进不去**——连证明「我是我」的机会都没有。改成验口令成功即清本人的两格预算。免凭据的登录/注册那两本账判据一个字没动（那里的「成功」随手可得，还预算会让枚举无限续命）。
- **审计落盘加路径掩码**：审计的 `detail` 是调用方可填的自由文本，一句异常原文就能把本机盘符路径写进 `audit.jsonl`。出口层早有这道网，落盘层没有；而审计的留存期与暴露面都比出口更大。复用同一份路径掩码实现，不再抄第二份。
- **个人面的模型服务写操作补齐审计**：新建/修改/删除三条写口原来零审计——冒名覆盖不会被记录，被拒的 400 也看不见。补上之后「这条私有模型是谁什么时候改的」有账可查，且密钥明文不进审计流。
- **PUT 的 id 口径统一**：请求体里的 id 与路径不一致时，过去静默以路径为准，而 MCP 面对同一件事是响亮的 400——两种口径并存，最坏结果是「客户端以为改的是 A、实际改的是 B」而没有任何一处告诉它。现在两路 PUT 共用一道闸：带了且不一致就 400，不带/纯空白/相同照旧放行。

## 正确性

- **编辑模型服务不再洗掉全站默认**：两端表单都硬发 `is_default=false`（表单上根本没有这一格），而存储层是整条替换——于是「改一次模型名字」就等于把全站那颗 ★ 摘掉，默认悄悄漂到另一条上，一句错都不说。改成与单价、上下文上限同一条「没带就保留」纪律。
- **嵌入返回值当场验形状与维度**：ChromaDB 在首次写入时按当次向量锁维度，之后后端换了维度不会报，只会在写入那一刻抛一个难以定位的参数错误。启动探测已兜住「库与后端不一致」，运行期这条补上：形状不对或维度变了都当场拒绝，不污染记忆库。

## 发版纪律

- **闸门补上「上一版内容还在不在」这一格**：过去只问「HEAD 是不是 tag 那一笔、说明在不在、线上是不是这一版」，**不问**「比起上一版我们丢了什么」。三枚 site-only tag 那次官网内容丢失，闸门全程绿灯就是因为没有这一格。现在取上一版 tag 与本版的**文件清单**之差——比清单而不是逐行比内容，是因为这一格要抓「整块内容被弄丢」，逐行比会让任何正常改动都红。

## 质量债

- **发版闸门读线上 build 不再走系统代理**：`urlopen` 的默认 opener 在 Windows 上会读环境变量与注册表代理设置——谁能改那组键，谁就能把闸门读到的版本串改道到一个自己复述的假地址上，随后「放行」一个根本没换过的包。改成显式空代理 opener，TLS 行为刻意不变。
- **「每处模型客户端必带自建连接」的判据从子串改成语法树**：旧的写法只要实参里出现那个词就算过——注释里写一句、字符串里提一嘴都算，真漏传反而看不见；而且遇到嵌套括号会断在中间误判。改成只认「实参里真有这个关键字参数」。
- **几处会腐烂的说法改正**：把写死的次数换成「若干次」并写明为什么不写死；把已被实测证伪的「某账号停用后恒 404」换成站得住的那条理由（站外地址的可用性不归我们控）；把判据源从不入库的目录改指已入库的文档。

## 边界与残余

- 不改模型配置、用户数据、API 行为、自助注册口径与更新通道；运行期 `data/version.json` 保持原样（仍宣告 0.36.9）。
- 安卓源码本版未动，**没有新安装包**。
- 交接文档里剩下的大多是产品功能欠账（导出路径改造、reload 状态机、第四出网站点证据等），需要设备验证或单独设计，不在本版射程内。
