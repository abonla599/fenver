# 真机验证指引：自带模型直连探测页

> **这份文档给谁看**：拿到一台安卓真机（或任何能开浏览器的手机），需要验证「用户自带的模型
> API Key 能不能在手机浏览器 / WebView 里真的跑通流式对话」的人。
>
> **核查结论（2026-10-04）**：`probe.html` 在当前部署的 `/site/` 下**已可达**——
> `GET https://ai.fenever.xyz/site/probe.html` 返回 HTTP 200，无需登录、无需鉴权。
> 真机可以直接打开，不需要重建 EXE 或做任何部署动作。

## 要验证什么

`backend/app/web/site/probe.html` 是一个**对本站后端零请求**的纯前端页面：它只和
用户填写的模型供应商说话，不碰 `/v1/*`、不读 cookie、不写 localStorage。它回答两个问题：

1. **手机浏览器 / 安卓 WebView 里，能不能从供应商拿到流式回答？**
   桌面 CDP 验得了协议，验不了移动 WebView 的混合内容与 CORS 差异。
2. **供应商到底回不回 `usage`？字段叫什么？**
   决定账本能不能"记账用回传、预算用估算"。

## 怎么跑

### 1. 打开手机浏览器，访问这个地址

```
https://ai.fenever.xyz/site/probe.html
```

不需要登录，不需要任何前置操作。如果打得开（能看到「自带模型直连探测」标题），说明
`/site/` 下的静态文件在真机上可达——这一步本身就是验收。

### 2. 填写供应商信息

| 字段 | 填什么 | 示例 |
| --- | --- | --- |
| Base URL | 模型供应商的 API 地址 | `https://api.deepseek.com` |
| 模型名 | 要测的模型标识 | `deepseek-chat` 或 `deepseek-flash` |
| API Key | 用户自己的 key（`sk-...`） | 只留在这台手机的内存里，刷新即无 |

**安全提示**：本页不存盘、不发送 key 到本站服务器。报告里也绝不出现 key 的任何片段
（连长度、首尾字符都不写）。复制出去的文本可以安全地贴给工程师看。

### 3. 点「跑全部六项」

六项检查依次执行，每项最多等 20 秒：

| # | 检查项 | 看什么 |
| --- | --- | --- |
| 1 | 流式连通 | 首字延迟、增量块数、总耗时、finish_reason |
| 2 | usage 回传 | 最后一个块里有没有 `usage` 字段，字段名叫什么 |
| 3 | 非流式 | 一次性返回能不能成（有些网关只放行其中一条路） |
| 4 | 错 key 的报错 | 故意用坏 key，看状态码与文案（期望 401/403） |
| 5 | 中途取消 | 生成到一半主动 abort()，看已收到的量与错误名 |
| 6 | 手动断网 | **这一项需要人工配合**：点「只跑第 6 项」，然后在生成过程中开飞行模式 |

### 4. 复制报告

跑完后点「复制报告」，得到的文本形状大致是：

```
直连探测报告 2026/10/4 15:30:00
UA: Mozilla/5.0 ...（识别为安卓 WebView）
页面: https://ai.fenever.xyz/site/probe.html
base: https://api.deepseek.com  model: deepseek-chat
key: 已填（不出现在报告里）

OK  1. 流式连通 —— 首字 320ms，增量 45 块 / 128 字，共 2103ms，finish=stop
OK  2. usage 回传 —— 回传了：{"prompt_tokens":14,"completion_tokens":28,"total_tokens":42}
OK  3. 非流式 —— 890ms，usage={"prompt_tokens":6,"completion_tokens":3,"total_tokens":9}
OK  4. 错 key 的报错 —— 状态码 401，文案：Authentication Fails...
OK  5. 中途取消 —— 2.5s 时主动中断：已收 12 块 / 45 字，aborted=true
OK  6. 手动断网 —— 断网如期失败：TypeError Failed to fetch
```

把这段文本发给工程师即可。

## 判据

- **六项全 OK**：这个供应商在这个手机上完全可用，pipeline.py 不需要改。
- **第 1 项 FAIL**：流式不通。看错误信息——是 CORS、是超时、还是供应商根本不支持流式。
- **第 2 项 FAIL**：供应商不回 `usage`。账本只能走非流式的 usage 或本地估算。
- **第 4 项 FAIL（状态码不是 401/403）**：供应商的鉴权行为异常，需要查。
- **第 6 项 FAIL（断网后居然跑完了）**：说明没真测到——确认是在**生成过程中**断的网。

## 注意事项

- **本页对本站后端零请求**：它不依赖本站的模型配置、不依赖登录态、不碰任何用户数据。
  所以它可以匿名公开访问，也不需要和"是不是我们的用户"扯上关系。
- **WebView 识别**：页面会自动检测 UA 里有没有 `; wv)` 或 `wv,`，如果是安卓 WebView
  会在报告里标注。这条信息帮助工程师判断"是浏览器行为还是 WebView 行为"。
- **超时上限 20 秒**：每项的每个 await 最多等 20 秒，超时会写进报告而不是卡住页面。
  这是从"第 4 项永远停在正在跑"那次事故里学来的——期限必须挂在 Promise 上，不依赖
  abort 是否真的能打断内核请求。

## 如果页面打不开

- **公网 502**：隧道或后端问题，见 `安装部署指南.md` 步骤 6 的两条 curl。
- **页面空白或 JS 报错**：浏览器版本太老（不支持 `fetch` 或 `ReadableStream`），
  换一个现代浏览器（Chrome / Edge / Firefox）再试。
- **CORS 报错**：供应商不支持浏览器直连（没回 `Access-Control-Allow-Origin`），
  这条路径走不通，需要走服务端代理——那是另一条路，不在本页范围内。
